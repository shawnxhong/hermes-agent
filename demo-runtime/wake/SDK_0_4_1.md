# AISP 0.4.1 wake integration

The Ubuntu 26.04 C++ SDK v0.4.1-261016-58480 supplies the runtime and bundled
OpenVINO libraries; Python wheels are not installed. The ops SDK lock records
archive/library hashes. Recompile the bridge and deploy its Python wrapper
atomically: the C ABI now accepts a source-language code and AEC settings.

The same mounted wake config.yaml owns:

```yaml
asr:
  source_language: auto
  hotwords: []  # Example only; deployments retain their existing list.
audio:
  aec: os
  aec_reference: default
```

Supported language codes: auto, zh, en, ja, yue, ko, de, fr, ru, it, sp, pt.
The SDK parses the code into its language enum and the bridge checks pipeline
retention. NOS is a detection label, not an input-language selection. Invalid
language or audio mode values fail config validation. Existing hotwords, aliases,
media-stop policy and EOS behavior remain independent of language selection.

AEC modes are os and none. Reference values are default, an exact PipeWire
node.name, or PLAYBACK_DEVICE:N. Each service start reads effective
`default.audio.sink`, never `default.configured.audio.sink`. SDK 0.4.1 Linux
is_default/index-zero selection does not represent the actual OS default and
invalid indices may silently select zero. The adapter therefore validates its
own mapping against SDK enumeration and the actual new PipeWire monitor link.
Duplicate descriptions are considered ambiguous and trigger fallback, not a guess.
The selected reference is fixed for this session: restart after output changes.

SDK enumeration and reference resolution can run before its internal PwDevice
initializes PipeWire. The bridge retains a balanced pw_init/pw_deinit reference
for its lifetime; enumeration also uses a balanced temporary reference. This
fixes the observed empty-enumeration/plugin-directory error without SDK patches.

AEC settings belong to MediaSession, not the ASR pipeline. Reference lookup,
AEC start or monitor-link validation failure releases the session and retries
once with the same microphone, aec=none and no reference. Plain capture failure
is a real startup error. AEC is not retried repeatedly during that run and the
requested YAML is not rewritten. Explicit none skips reference lookup entirely.

Status events: aec_reference_selected (node + SDK index), aec_fallback (reason),
audio_capture_ready (requested/effective mode). Language is printed by the bridge
at pipeline initialization. These distinguish configured AEC from actual use.
Keep GPU ASR, CPU VAD, 128 tokens, 500 ms chunks and existing backlog settings.

After editing the mounted YAML: stop voice, restart the aisp-wake Compose
service, then run hermes-box-voice start. That command alone does not reload an
already-running wake service. Configuration path/rollback and per-host evidence
are recorded in the paired ops handoff. AEC addresses playback echo, not fan noise;
synthetic regressions do not establish microphone accuracy for human speech.
